## 1. 운영체제와 컴퓨터시스템의 구조
### 운영체제의 종류
운영체제는 앞단의 인터페이스를 기준으로 GUI와 CUI로 나뉜다.
- **GUI(Graphical User Interface)**: 그래픽을 사용하여 컴퓨터와 상호작용하는 인터페이스. windowOS, macOS 등이 대표적.
- **CUI(Character User Interface)**: 키보드만으로 문자를 기반으로 컴퓨터와 상호작용하는 인터페이스. MS-DOS, ChatGPT 등이 대표적.

### 운영체제의 역할
운영체제의 커널이 담당하는 역할들이다.
- CPU 스케줄링과 프로세스 상태관리
- 메모리관리
- 디스크 파일 관리
- I/O 디바이스 관리

### 운영체제의 구조
- 유저프로그램
- 인터페이스(GUI 또는 CUI)
- 시스템콜(system call)
- 커널(I/O 드라이버, 파일시스템 등)
- 하드웨어(hardware)

### 컴퓨터 시스템의 구조
- **CPU**: 인터럽트에 의해 메모리에 존재하는 명령어를 해석해서 실행하는 일꾼
- **DMA컨트롤러**: CPU의 일을 보조하는 일꾼
- **메모리**: 전자회로에서 데이터, 상태 등을 기록하는 장치(작업장)
- **타이머**: 특정 프로그램에 시간을 다는 역할
- **디바이스 컨트롤러**: IO디바이스들의 작은 CPU
- **로컬버퍼**: 디바이스에 달려 있는 작은 메모리

### CPU 구성 요소
산술논리연산장치, 제어장치, 레지스터로 구성된다.
- **산술논리연산장치(ALU)**: 덧셈, 뺄셈, 곱셈, 나눗셈 등 산술연산과 논리연산을 하는 회로장치
- **제어장치(CU)**: 프로세스의 조작을 지시하며 명령어들을 읽고 해석하며 데이터 처리를 위한 순서를 결정
- **레지스터**: CPU안에 있는 매우 빠른 임시기억장치

## 2. 인터럽트
어떤 신호가 들어왔을 때 CPU를 잠깐 정지시키는 것. 0으로 숫자를 나누는 산술 연산오류, 프로세스 오류, 키보드/마우스 등 IO 디바이스 사용, 우선순위가 높은 프로세스의 발생 등으로 발생한다.

CPU는 명령어를 순차적으로 실행하다가 인터럽트가 발생되면 인터럽트 벡터로 점프해서 인터럽트 핸들러 함수(ISR)을 실행한 후, 인터럽트가 종료되면 다시 순차적으로 실행한다.

### 하드웨어 인터럽트
IO 디바이스 등 하드웨어에서 발생하는 인터럽트. 마우스 클릭, 디스크 파일 읽기/쓰기 작업 완료 시 발동된다.

### 소프트웨어 인터럽트
트랩(trap)이라고도 한다. 프로세스 오류, 프로세스의 종료/시작 등을 기반으로 프로세스에서 발생하는 인터럽트. 하드웨어 인터럽트보다 우선순위가 높다.

## 3. 시스템콜과 modebit
### 시스템콜
운영체제가 커널에 접근하기 위한 인터페이스이며 유저 프로그램이 운영체제의 서비스를 받기 위해 커널 함수를 호출할 때 거쳐가는 통로다. 프로세스 관리, 파일관리, 디바이스 관리, 시간/날짜 관련 시스템, 프로세스 간 통신 시 사용된다.

### 시스템 콜의 과정 (예: I/O 요청)
1. 유저 프로그램이 I/O 요청 트랩 발동
2. 올바른 I/O 요청인지 확인
3. 유저 모드가 시스템콜을 통해 커널모드로 변환
4. 이후 커널함수를 실행

### 핵심 개념
- **커널함수**: 커널 안에 있는 여러개의 함수(native function)
- **커널**: 운영체제의 핵심 부분이자 시스템콜을 제공하며 보안, 메모리, 프로세스, 파일 시스템, I/O 디바이스 관리를 담당
- **유저 모드**: 유저가 접근할 수 있는 영역을 제한적으로 두며 컴퓨터 자원에 함부로 침범하지 못하는 모드
- **커널 모드**: 모든 컴퓨터 자원에 접근할 수 있는 모드
- **modebit**: 1 또는 0의 값을 가지는 플래그 변수. 1은 유저모드, 0은 커널모드

### 시스템 콜의 장점
유저프로그램은 복잡한 파일 시스템과 프로세스 생성 등에 대한 내부동작을 신경쓸 필요가 없으며, 운영체제의 관리하에 프로그램이 운영되므로 시스템의 안정성과 보안이 강화된다.

## 4. 메모리계층
메모리 계층은 레지스터, 캐시, 주기억장치, 보조기억장치로 구성된다.
- **레지스터**: CPU 내의 작은 메모리, 휘발성, 속도 가장 빠름, 기억 용량 가장 적음
- **캐시**: CPU 내의 L1, L2 캐시. 휘발성, 속도 빠름, 기억 용량 적음
- **주기억장치**: RAM. 휘발성, 속도 보통, 기억 용량 보통
- **보조기억장치**: HDD, SSD. 비휘발성, 속도 낮음, 기억 용량 많음

### 계층이 존재하는 이유
- **더 빠른 접근과 처리속도 증가**: 자주 쓰는 데이터를 작은 캐시 메모리에 두면 빠르게 접근 가능
- **비용의 효율성**: 캐시메모리는 비싸고 아래로 갈수록 저렴하므로 비용 효율적 사용 가능
- **자원의 효율적 사용**: 자주 접근하는 데이터는 빠른 메모리에, 덜 접근하는 데이터는 느린 메모리에 저장

## 5. 가상메모리
컴퓨터가 실제로 이용가능한 메모리 자원을 추상화하여 사용자에게 매우 큰 메모리로 보이게 만드는 메모리 관리기법이다. 페이지 테이블, MMU, TLB, 페이지 폴트 등이 어우러진 시스템을 통틀어서 말한다.

- **MMU**: CPU와 메모리 사이에 위치한 하드웨어 컴포넌트로, 가상 주소와 물리 주소 사이의 변환을 담당
- **페이지**: 가상 메모리를 사용하는 최소 크기 단위
- **프레임**: 실제 메모리를 사용하는 최소 크기 단위

### 페이지테이블
가상 메모리는 가상주소와 실제주소가 매핑되어 있는 자료구조인 페이지 테이블로 관리되며, 속도 향상을 위해 캐싱계층인 TLB를 쓴다. 가상주소에서 바로 페이지테이블로 가는 게 아니라 TLB에서 먼저 확인하고 없다면 페이지테이블로 가서 실제주소를 가져온다.

### 페이지폴트
프로세스가 참조하려는 주소가 가리키는 페이지가 현재 물리 메모리(RAM)에 없을 때 발생하는 현상. 가상메모리는 작은 메모리를 매우 큰 메모리로 보이게끔 하기 때문에 참조하려는 메모리 영역이 실제 메모리에 없을 수 있다.

#### 페이지 폴트 이후의 과정
1. OS에게 트랩을 전송하고 OS는 페이지 폴트가 유효한 접근인지 점검 (비정상적이면 강제 종료)
2. OS는 물리 메모리에서 빈 프레임이 있는지 확인
   - **빈 프레임이 있을 경우**: 디스크에서 필요한 페이지를 메모리로 적재(Swap-in)
   - **빈 프레임이 없을 경우**: 페이지 교체 알고리즘을 수행하여 기존 페이지를 디스크로 내보내고(Swap-out), 빈 프레임을 확보한 뒤 필요한 페이지를 가져옴(Swap-in)

> 메모리 접근 시간은 수백 나노초 수준, 디스크 접근 시간은 수 밀리초 수준으로 페이지 폴트가 자주 발생하면 CPU 이용률이 저하된다.

### 스레싱
실제 프로세스 실행보다 스와핑 작업에 대부분의 시간이 소요되는 현상. 페이지 폴트가 빈번하게 발생하면 스와핑이 과도하게 일어나 CPU 이용률이 낮아진다. 운영체제는 CPU 사용률을 보완하고자 추가 프로세스를 메모리에 적재하는데, 이는 메모리 부족과 페이지 폴트의 악순환을 일으켜 시스템 성능이 급격히 저하된다.

#### 스레싱 해결 방법
- **하드웨어적 해결**: 메모리를 늘리거나 HDD를 SSD로 교체
- **작업세트(Working Set)**: 프로세스의 과거 사용이력을 기반으로 많이 사용하는 페이지집합을 만들어 한꺼번에 미리 메모리에 로드
- **PFF(Page Fault Frequency)**: 각 프로세스의 페이지 폴트 발생 빈도를 모니터링하여 메모리 프레임 할당량을 동적으로 조절
  - 상한선 초과 시: 더 많은 프레임을 할당하여 작업세트 확장
  - 하한선 미달 시: 일부 프레임을 회수하여 다른 프로세스에 재할당

### 가상 메모리의 장점
- **메모리 효율적 사용**: 실제로 필요한 시점에 해당 메모리 페이지만 동적으로 불러옴(Demand Paging)
- **메모리 과잉 할당**: 실제 RAM보다 훨씬 큰 주소 공간을 사용 가능
- **프로세스 간 메모리 보호**: 각 프로세스는 독립적인 가상 주소 공간을 가져 다른 프로세스에 영향 X
- **메모리 접근 제어**: 페이지별로 읽기, 쓰기, 실행 권한 설정 가능 → 버퍼 오버플로우, 코드 인젝션 등 보안 위협 예방

## 6. 페이지히트와 페이지미스
- **페이지 히트(Page Hit)**: 프로세스가 요청한 페이지가 이미 메모리에 적재되어 있어 바로 접근 가능한 상황
- **페이지 미스(Page Miss)**: 프로세스가 요청한 페이지가 메모리에 없는 상황

### 페이지미스와 페이지 폴트의 관계
모든 페이지 폴트는 페이지 미스로 인해 발생하지만, 모든 페이지 미스가 페이지 폴트로 이어지지는 않는다.
- **접근 권한 오류**: 권한 위반으로 페이지미스가 발생하지만 메모리로 로드하지 않아 페이지 폴트로 이어지지 않음
- **성능최적화 프리페칭**: 미리 요청한 페이지가 사용되기 전에 다른 데이터로 덮어쓰일 경우

## 7. 페이지교체 알고리즘
스와핑이 일어날 때 페이지교체 알고리즘에 의해 페이지가 교체되며, 최대한 스와핑을 적게 하는 것을 목표로 한다.

### 오프라인 알고리즘 (LFD)
LFD(Longest Forward Distance)는 가장 좋은 알고리즘으로 일컬어진다. 더 이상 참조되지 않거나 가장 늦게 다시 참조되는 페이지와 지금 요청된 페이지를 바꾸는 알고리즘이다. 향후 요청을 모두 알고 있다는 가정하에 가장 효율적인 교체를 하지만, 실제 시스템에서는 미래의 요청을 알 수 없어 직접 구현 불가능하다. 다른 알고리즘과의 성능비교에 대한 상한선을 제공한다.

### FIFO (First In First Out)
가장 먼저 온 페이지부터 교체하는 방법.

### LRU (Least Recently Used)
최근에 사용되지 않은 페이지(참조가 가장 오래된 페이지)를 바꾸는 방법. 각 페이지마다 최근 사용한 횟수를 나타내는 자료구조가 필요할 수 있다.

### NUR (Not Used Recently)
LRU에서 발전한 알고리즘으로 NRU 또는 clock 알고리즘이라고도 한다. 0과 1을 가진 비트를 두고(1은 최근 참조됨, 0은 참조되지 않음), 시계 방향으로 돌면서 0을 찾아 해당 페이지를 교체하고 1로 바꾼다. 한 바퀴 도는 동안 사용되지 않으면 0이 된다.

### LFU (Least Frequently Used)
가장 참조 횟수가 적은 페이지를 교체하는 알고리즘.

## 8. 프로세스와 스레드
### 프로세스(process)
컴퓨터의 메모리에 올라와 실행되고 있는 프로그램. task와 같은 의미로 쓰인다. 하나의 스레드로 이루어진 싱글스레드 프로세스, 여러개의 스레드로 이루어진 멀티스레드 프로세스로 나뉜다.

### 스레드(thread)
프로세스 내 작업의 흐름을 지칭한다.

### 프로세스와 스레드의 차이
1. 프로세스는 코드, 데이터, 스택, 힙 메모리 영역을 기반으로 작업하는 반면, 스레드는 스택 메모리를 제외한 다른 메모리 영역을 프로세스 내 다른 스레드들과 공유하기 때문에 메모리적 이점이 있다.
2. 프로세스는 다른 프로세스와 격리되어 있어 통신 시 IPC를 사용해야 하지만, 스레드는 격리되어 있지 않아 그냥 통신할 수 있어 더 빠르다.
3. 프로세스는 한 프로세스에 문제가 생겨도 다른 프로세스에 영향을 끼치지 않지만, 스레드는 한 스레드에 문제가 생기면 다른 스레드에도 영향을 끼친다.
4. 프로세스는 생성과 종료에 더 많은 시간이 들며, 스레드는 더 적은 시간이 든다.

## 9. 프로그램의 컴파일 과정
프로그램은 컴파일러가 컴파일 과정을 거쳐 컴퓨터가 이해할 수 있는 기계어로 번역되어 실행될 수 있는 파일이 된 것이다.

### 1. 전처리(Preprocessor)
소스코드의 주석제거, `#include` 등 헤더파일 병합, 매크로 치환을 수행한다.

### 2. 컴파일러(Compiler)
오류처리, 코드최적화 작업을 하여 어셈블리어로 변환한다.

### 3. 어셈블러(Assembler)
어셈블리어를 목적코드(object code)로 변환한다. 리눅스에서는 `.o` 확장자를 가진다.

### 4. 링커(Linker)
프로그램 내 라이브러리 함수 등과 결합해 실행파일이 만들어진다. `.exe`, `.out` 확장자를 가진다.

## 10. 프로세스의 메모리 구조
운영체제는 프로세스에 적절한 메모리를 할당하는데, 위에서부터 스택, 힙, 데이터 영역(BSS, Data segment), 코드 영역으로 나누어진다. 스택은 위 주소부터, 힙은 아래 주소부터 할당된다.

- **스택**: 지역변수, 매개변수, 함수가 저장. 컴파일 시 크기가 결정되나 함수 호출에 따라 런타임에도 크기 변경 [동적]
- **힙**: 동적 할당 시 사용되며 런타임에 크기 결정 [동적]
- **데이터영역**: BSS와 Data 영역으로 나뉘고 정적할당 담당 [정적]
- **코드영역**: 소스코드 저장 [정적]

### 정적할당
컴파일 단계에서 메모리를 할당한다.
- **BSS segment**: 전역변수, static, const 중 0으로 초기화 또는 초기화되지 않은 변수
- **Data segment**: 전역변수, static, const 중 0이 아닌 값으로 초기화된 변수
- **Code/Text segment**: 프로그램의 코드

### 동적할당
런타임 단계에서 메모리를 할당받는다.
- **Stack**: 지역변수, 매개변수, 실행되는 함수에 의해 늘어나거나 줄어드는 메모리 영역. 함수 호출마다 호출 환경 등 특정 정보가 stack에 저장된다. 재귀함수 호출 시 새로운 스택 프레임이 매번 사용되어 변수 집합이 다른 인스턴스 변수를 방해하지 않는다.
- **Heap**: 동적으로 할당되는 변수들을 담는다. `malloc()`, `free()` 함수로 관리하며 동적 자료구조(예: vector)는 내부적으로 heap영역을 사용한다.
