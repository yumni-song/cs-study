## 캐시히트와 캐시미스
### 캐시
데이터를 미리 복사해 놓는 임시 저장소이자, 속도 차이가 나는 장치 간의 병목 현상을 줄이기 위한 메모리다. 이를 통해 데이터 접근 시간을 단축하고 재계산 시간을 절약할 수 있다.

대표적인 예로 CPU 레지스터가 있다. CPU가 메모리에서 데이터를 가져오는 시간이 너무 크기 때문에 중간에 레지스터 계층을 둬서 속도차이를 해결한다.

- **캐시 히트**: 캐시에서 원하는 데이터를 찾은 것
- **캐시 미스**: 캐시에서 원하는 데이터를 찾지 못해 메모리로 가서 가져오는 것

서비스 내부에서도 자주 활용된다.
- 데이터베이스 앞에 Redis를 캐시 계층으로 둔 사례
- 웹서버 앞단에 Nginx 서버를 캐시 계층으로 둔 사례

### 지역성의 원리
캐시는 자주 사용하는 데이터를 기반으로 설정해야 하며, 이때 지역성을 기준으로 한다.

- **시간 지역성(temporal locality)**: 최근 사용한 데이터에 다시 접근하려는 특성. 예를 들어 반복문에서 변수 `i`에 계속 접근하는 경우.
- **공간 지역성(spatial locality)**: 최근 접근한 데이터 근처의 공간에 접근하는 특성. 예를 들어 배열의 연속된 인덱스에 접근하는 경우.

## 캐시매핑
캐시는 메모리보다 항상 작기 때문에 효율적인 매핑이 중요하며, 직접 매핑, 연관 매핑, 집합-연관 매핑 세 가지 방식이 있다.

운영체제는 메모리를 동일 크기의 페이지(보통 4KB)로 나누어 `<P, D>`로 관리한다.
- **P (Page Number)**: 페이지 번호
- **D (Page offset)**: 페이지번호로부터 해당 주소까지의 거리

가상주소가 실제주소로 변환될 때 D는 변환되지 않고 P만 변환된다. 따라서 매핑은 P 부분에서 일어난다.

### 직접 매핑(Direct Mapping)
메모리의 특정 블록은 특정 캐시 라인에만 매핑할 수 있는 방식.

예를 들어 메모리가 100개 페이지, 캐시가 5개 페이지라면 1번 캐시는 1~20번 메모리, 2번 캐시는 21~40번 메모리... 식으로 매핑된다.

P를 `{tag, bd}`로 세분화하여 `<tag, bd, D>` 구조로 구현하며, bd(block distance)가 같은 라인끼리만 매핑된다.

- **장점**: 해당 블록만 확인하면 되므로 처리가 빠름
- **단점**: 스와핑이 빈번하게 발생할 수 있음

### 연관 매핑(Associative Mapping)
순서를 일치시키지 않고 관련 있는 캐시와 메모리를 매핑하는 방식. 메모리의 컨텐츠가 캐시의 어느 위치에도 올라갈 수 있다.

- **장점**: 스와핑이 덜 일어남
- **단점**: 캐시의 모든 블록을 탐색해야 해서 직접 매핑보다 느림

### 집합 연관 매핑(Set Associative Mapping)
집합을 나누고(직접매핑처럼) 해당 집합 내에서는 bd만 같으면 어떤 블록에도 들어올 수 있게 한다. 직접매핑의 빠른 탐색과 연관매핑의 스와핑 완화 장점을 모두 갖는다.

## 메모리할당 - 연속할당
프로그램에 필요한 메모리를 할당할 때 시작 위치와 크기를 기반으로 할당하며, 연속할당과 불연속할당으로 나뉜다.

**연속 할당(contiguous memory allocation)**은 메모리에 연속적인 공간을 할당하는 방식으로, 고정분할방식과 가변분할방식이 있다.

### 고정분할방식
메모리를 미리 같은 크기로 분할해서 할당하는 방식.
- **내부단편화(internal fragmentation)** 발생: 프로그램이 필요한 공간보다 더 많은 메모리가 할당되어 내부에 조각이 생기는 현상. 추후 메모리 할당이 어려워질 수 있음.

### 가변분할방식
프로그램에 필요한 만큼 동적으로 할당하는 방식. 내부단편화를 줄일 수 있지만 **외부단편화(external fragmentation)** 가 발생할 수 있다.

> 외부단편화: 동적 할당 후 남은 외부의 작은 조각들 때문에, 조각들의 합은 충분하지만 큰 프로그램을 할당하지 못하는 현상.

가변분할방식의 세 가지 방법:
- **최초적합(first fit)**: 위/아래부터 시작해 빈 공간(홀)을 찾으면 바로 할당
- **최적적합(best fit)**: 필요한 메모리 크기 이상인 공간 중 가장 작은 홀에 할당
- **최악적합(worst fit)**: 프로세스 크기와 가장 많이 차이가 나는 홀에 할당

> 홀(hole): 할당할 수 있는 비어 있는 메모리 공간

최악적합은 같은 크기의 작은 요청이 연속적으로 들어올 때 오히려 단편화를 줄일 수 있다.

## 메모리할당 - 불연속할당
**불연속할당(non-contiguous memory allocation)**은 메모리를 쪼개어 서로 다른 위치에 할당하는 방식으로 현대 운영체제가 사용한다. 페이징, 세그멘테이션, 페이지드 세그멘테이션이 있다.

### 페이징(Memory Paging)
동일한 크기(보통 4KB)의 페이지 단위로 나누어 서로 다른 위치에 프로세스를 할당한다.
- **장점**: 홀 크기가 균일하지 않은 문제(외부단편화) 해결
- **단점**: 주소 변환을 페이지별로 해야 해서 복잡해짐, 내부단편화 발생 가능

### 세그멘테이션(Memory Segmentation)
페이지 단위가 아닌 의미 단위인 세그먼트로 나누는 방식. 코드, 데이터, 스택, 힙 등으로 나누거나 함수 단위로도 나눌 수 있다.
- **장점**: 공유와 보안 측면에서 좋음, 내부단편화 해결
- **단점**: 홀 크기가 균일하지 않아 외부단편화 발생 가능

### 페이지드 세그멘테이션(Paged Segmentation)
세그멘테이션으로 나눈 뒤 해당 세그먼트를 동일한 크기의 페이지로 다시 나누는 방식.

## PCB와 컨텍스트 스위칭
### PCB
PCB(Process Control Block)는 운영체제가 관리하는 프로세스 메타데이터를 저장한 데이터 블록이다. 커널 스택에 저장되며, 프로세스가 생성될 때마다 고유의 PCB가 만들어지고 종료 시 제거된다.

#### PCB의 구조
- **프로세스 상태**: 대기중, 실행중 등
- **프로세스 번호(PID)**: 고유 식별 번호
- **프로그램 카운터(PC)**: 다음 실행할 명령의 주소 포인터
- **레지스터**: 레지스터 관련 정보
- **메모리 제한**: 프로세스의 메모리 관련 정보
- **열린 파일 정보**: 프로세스가 연 파일 목록

> 커널스택: 가상 메모리는 사용자공간과 커널공간으로 구분되며, 커널스택은 가상 메모리 주소의 윗부분으로 커널모드에서만 접근 가능하다.

### 컨텍스트 스위칭
PCB를 기반으로 프로세스의 상태를 저장하고 다시 복원시키는 과정. 프로세스 종료나 인터럽트에 의해 발생한다.

#### 컨텍스트 스위칭의 비용
1. **유휴시간 발생**: 스위칭마다 프로세스 당 유휴시간 발생
2. **캐시미스**: 잘못된 주소 변환을 막기 위한 캐시 클리어로 인해 캐시미스 발생
3. **오버헤드**: 중단된 작업 상태(레지스터, PC, 메모리 매핑 등) 저장과 새 작업 상태 로드에 따른 오버헤드

#### 스레드에서의 컨텍스트 스위칭
스레드는 스택 영역을 제외한 모든 메모리를 공유하기 때문에 비용이 더 적고 시간도 더 적게 걸린다.

## 16. 프로세스의 상태
프로세스의 상태는 다음과 같이 구성된다. (ready suspended와 blocked, blocked suspended를 묶어 waiting 상태라고 부르기도 함)

### 생성 상태(create/new)
프로세스가 `fork()` 또는 `exec()` 함수로 생성된 상태. 이때 PCB가 할당된다.
- **fork()**: 부모 프로세스의 주소 공간을 복사해 자식 프로세스 생성 (비동기 작업은 상속하지 않음)
- **exec()**: 새롭게 프로세스를 생성하는 함수

### 대기 상태(ready)
메모리 공간이 충분하면 메모리를 할당받고, 준비큐에서 CPU 소유권이 넘어오기를 기다리는 상태.

### 대기 중단 상태(ready suspended)
준비큐가 꽉 차서(메모리 부족) 일시 중단된 상태.

### 실행 상태(running)
CPU 소유권과 메모리를 할당받아 명령어를 수행 중인 상태. CPU burst가 일어났다고 표현한다.

### 중단 상태(blocked)
어떤 이벤트가 발생한 이후 기다리며 프로세스가 차단된 상태. 예를 들어 프린트 인쇄 요청으로 인한 인터럽트 발생 시 잠시 변경되는 상태.

### 일시 중단 상태(blocked suspended)
중단된 상태에서 다시 실행하려 했지만 메모리 부족으로 일시 중단된 상태.

### 종료 상태(terminated/exit)
프로세스 실행이 완료되어 자원을 반납하고 PCB가 삭제되는 상태. 자연 종료뿐 아니라 부모 프로세스에 의한 비자발적 종료(abort)도 가능하다.

## 멀티프로세싱과 멀티스레딩
### 멀티프로세싱
여러 개의 프로세스를 통해 동시에 두 가지 이상의 일을 수행한다. 일부 프로세스에 문제가 생겨도 다른 프로세스에 영향을 주지 않아 **격리성과 신뢰성이 높다**.

### 멀티스레딩
프로세스 내 작업을 멀티스레드로 처리. 스레드끼리 자원을 공유하고 프로세스보다 가벼워 **효율성이 높다**. 다만 한 스레드의 문제가 다른 스레드 및 프로세스 전체에 영향을 줄 수 있다.

> 브라우저는 멀티프로세스이자 멀티스레드 아키텍처를 가진 소프트웨어다. (브라우저 프로세스, 렌더러 프로세스, GPU 프로세스, 플러그인 프로세스 등으로 구성)

## IPC
**IPC(Inter-Process Communication)**는 프로세스끼리 데이터를 주고받고 공유 데이터를 관리하는 메커니즘이다. 공유메모리, 파일, 소켓, 파이프, 메시지 큐가 있다.

### 공유메모리
여러 프로세스가 메모리를 공유. 데이터 복사 오버헤드가 없어 **IPC 중 가장 빠르다**. 같은 메모리 영역을 공유하므로 동기화가 필요하다.

### 파일
디스크에 저장된 데이터를 기반으로 통신.

### 소켓
네트워크 인터페이스(TCP, UDP, HTTP 등)를 기반으로 통신.

### 파이프
- **익명 파이프(anonymous pipe)**: 프로세스 사이에 FIFO 기반 통신채널을 만들어 통신. 단방향이므로 양방향 통신을 위해서는 2개의 파이프가 필요. 부모-자식 프로세스 간에만 사용 가능하며 다른 네트워크에서는 사용 불가.
- **명명 파이프(named pipe)**: 익명 파이프의 확장된 개념. 부모-자식뿐 아니라 다른 네트워크상에서도 통신 가능. 보통 서버/클라이언트용 파이프를 구분해 동작.

### 메시지 큐
메시지를 큐(queue) 자료구조 형태로 관리하는 버퍼를 만들어 통신.
1. 프로세스가 메시지 송수신 전에 큐를 초기화
2. 보내는 프로세스의 메시지가 큐에 복사되어 받는 프로세스에 전달

## 19. 공유자원과 경쟁상태 그리고 임계영역
### 공유 자원
시스템 안에서 각 프로세스/스레드가 함께 접근할 수 있는 모니터, 프린터, 메모리, 파일, 데이터 등의 자원이나 변수.

### 경쟁 상태(race condition)
공유 자원을 둘 이상의 프로세스/스레드가 동시에 읽거나 쓰는 상황. 접근 타이밍에 따라 결과가 달라질 수 있는 상태.

### 임계 영역(critical section)
둘 이상의 프로세스/스레드가 공유자원에 접근할 때 순서 등으로 결과가 달라지는 코드 영역. 한 번에 둘 이상의 프로세스/스레드가 들어갈 수 없게 설계된다.

```
do {
    lock();
    {임계 영역}
    unlock();
}
```

### 경쟁 상태 관리의 중요성
- **데이터 정합성(data consistency)**: 예상되는 데이터 값과 다른 것 (예: 0원이어야 하는데 1000원)
- **데이터 무결성(data integrity)**: 데이터 규칙을 위반하지 않는 것 (예: 0원인데 출금하는 것)

## 20. 뮤텍스, 세마포어, 모니터
경쟁상태 해결의 대표적 방법으로 뮤텍스, 세마포어, 모니터 세 가지가 있다. 이들은 다음 세 조건을 만족시킨다.

- **상호 배제(mutual exclusion)**: 한 프로세스가 임계 영역에 들어가면 다른 프로세스는 들어갈 수 없음
- **한정 대기(bounded waiting)**: 특정 프로세스가 영원히 임계 영역에 들어가지 못하는 것을 방지
- **진행의 융통성(progress)**: 임계영역을 아무도 사용하지 않으면 외부 프로세스가 들어갈 수 있고, 프로세스끼리 서로 방해하지 않음

### 뮤텍스(Mutex)
공유 자원을 `lock()`으로 잠그고 사용 후 `unlock()`으로 해제하는 객체 lock 기반의 방법. 한 번에 하나의 프로세스만 임계영역에 있을 수 있다. (예: 변기 1개인 화장실)

### 세마포어(Semaphore)
일반화된 뮤텍스. 정수 S와 `wait()`, `signal()` 함수로 접근을 처리한다.
- **S**: 현재 쓸 수 있는 공유자원의 수
- **wait()**: S를 1 감소. S가 음수가 되면 대기열에 프로세스를 넣고 차단
- **signal()**: S를 1 증가. S가 0 이하면 대기열의 프로세스를 깨움

> signal()은 V(), wait()는 P()라고도 한다.

#### 바이너리 세마포어
0과 1의 두 값만 가지는 세마포어. 뮤텍스와 유사하지만 엄밀히는 다르다.
- 뮤텍스: **잠금 메커니즘** 기반 상호배제
- 세마포어: **신호 메커니즘** 기반 상호배제

#### 카운팅 세마포어
여러 개의 값을 가질 수 있는 세마포어. (예: 5명만 로그인 가능한 게임)

### 모니터(Monitor)
공유자원을 숨기고 접근 인터페이스만 제공하는 객체. 작업을 순차 처리한다.

#### 모니터와 세마포어의 차이
- **모니터**: 구현이 쉽고, 한 번에 하나의 프로세스만 접근 가능. **상호배제가 자동**. 인터페이스 기반.
- **세마포어**: 구현이 어렵고, 여러 프로세스가 동시 접근 가능. **상호배제를 명시적으로 구현**해야 함. 정수 변수 기반.

## 21. 교착 상태(Deadlock)
교착상태는 두 개 이상의 프로세스가 서로의 자원을 기다리며 중단된 상태다.

### 교착 상태의 4가지 필요조건
- **상호 배제**: 한 프로세스가 자원을 독점하며 다른 프로세스는 접근 불가
- **점유 대기**: 특정 프로세스가 점유한 자원을 다른 프로세스가 요청하며 대기
- **비선점**: 다른 프로세스의 자원을 강제로 가져올 수 없음
- **환형 대기**: 서로가 서로의 자원을 요구하는 상황

> 4가지 조건이 모두 충족되어도 교착상태가 발생하지 않을 수 있지만, 4가지가 모두 충족되어야 교착상태가 일어날 수 있다.

### 교착 상태의 해결 방법
1. 자원 할당 시 애초에 조건이 성립되지 않도록 설계
2. 은행원 알고리즘으로 교착 상태 가능성이 없을 때만 자원 할당
3. 교착 상태 발생 시 사이클을 찾아 관련 프로세스를 하나씩 제거
4. 교착 상태 발생 시 사용자가 작업 종료 (현대 운영체제 채택, '응답 없음'이 그 예)

### 은행원 알고리즘(Banker's Algorithm)
교착상태 회피 알고리즘. 총 자원량과 현재 할당량을 기준으로 안정/불안정 상태로 나누고 안정 상태로 가도록 자원을 할당한다.

- **안정상태**: 프로세스의 최대자원요구량을 운영체제가 충족시킬 수 있는 상태
- **불안정상태**: 안전상태로 가는 순서열이 존재하지 않는 상태

#### 은행원 알고리즘의 구조
- `available[i]`: 운영체제가 줄 수 있는 자원의 양
- `max[i][j]`: 프로세스 i가 자원 j를 최대 요청할 수 있는 양
- `allocation[i][j]`: 프로세스 i에 자원 j를 할당한 양
- `need[i][j]`: 프로세스 i가 자원 j를 추가 요청하는 양
- `finish[i]`: 프로세스 i의 요청을 만족할 수 있는지 표시하는 불리언

#### 은행원 알고리즘 순서
1. `request[i] <= need[i]`: 불충족 시 오류
2. `request[i] <= available[i]`: 불충족 시 대기
3. `request[i]` 값이 `available[i]`에 더해지고 `need[i]`에서 빼짐
4. 모든 프로세스에 대해 반복 후 모든 `finish[i]`가 True면 안정상태

#### 은행원 알고리즘의 단점
- 최대 자원 수 예측이 어려움
- 자원 소모량 증가
- 프로그램 수가 가변적이라 적용이 어려움

## 22. CPU 스케줄링 알고리즘 - 비선점형
효율적인 스케줄링의 기준:
1. CPU 사용률이 높은가?
2. 단위 시간당 처리량이 높은가?
3. 대기 시간이 짧은가?

**비선점형(non-preemptive)**: 프로세스가 스스로 CPU 소유권을 포기하는 방식. 강제 중지하지 않으므로 컨텍스트 스위칭 부하가 적다.

### FCFS (First Come, First Served)
가장 먼저 온 프로세스부터 처리. 길게 수행되는 프로세스 때문에 준비 큐에서 오래 기다리는 **convoy effect**가 발생할 수 있다.

### SJF (Shortest Job First)
실행 시간이 가장 짧은 프로세스를 먼저 실행. 평균 대기 시간이 가장 짧지만, 긴 프로세스가 실행되지 않는 **starvation** 발생 가능. 실제로는 실행 시간을 알 수 없어 과거 실행 시간으로 추측한다.

### 우선순위(Priority)
SJF의 starvation 단점을 보완하기 위해 오래된 작업일수록 우선순위를 높이는 **aging** 방법을 사용. 우선순위는 작업 시간, 메모리 요구사항, 열린 파일 수, 평균 CPU 사용량 등을 고려해 설정한다.

## CPU 스케줄링 알고리즘 - 선점형
**선점형(preemptive)**: 현대 운영체제가 사용하는 방식. 알고리즘에 의해 프로세스를 강제 중단시키고 다른 프로세스에 CPU 소유권을 할당할 수 있다.

### 라운드 로빈(Round Robin)
각 프로세스에 동일한 할당 시간을 주고, 시간 내에 끝나지 않으면 다시 준비큐 뒤로 보내는 알고리즘.
- 할당 시간이 크면 FCFS와 같아짐
- 할당 시간이 작으면 컨텍스트 스위칭이 잦아 오버헤드 증가
- 전체 작업 시간은 길어지지만 평균 응답 시간은 짧아짐
- 로드밸런서의 트래픽 분산 알고리즘으로도 사용됨

q만큼의 할당 시간이 N개 프로세스에 부여되면 `(N-1)*q` 시간 후 자기 차례가 온다.

### SRF (Shortest Remaining Time First, SRTF)
SJF의 선점형 버전. 중간에 더 짧은 작업이 들어오면 수행 중인 프로세스를 중지하고 짧은 프로세스를 먼저 수행한다.

### 다단계 큐(Multilevel Queue)
우선순위에 따라 여러 개의 준비큐를 사용하고, 큐마다 다른 스케줄링 알고리즘(RR, FCFS 등)을 적용. 큐 간 프로세스 이동이 안 되므로 스케줄링 부담은 적지만 유연성이 떨어진다. 낮은 큐의 프로세스가 처리되지 않는 **기아현상(starvation)** 발생 가능.

### LFD 알고리즘이 최적인 이유
오프라인 알고리즘 LFD(Longest Forward Distance)와 임의의 다른 알고리즘 KKG를 비교해보자.

KKG는 다음과 같다:
1. 요청 1, 2, ..., i까지는 LFD와 동일하게 처리
2. 요청 i+1부터 LFD와 다르게 처리

페이지 폴트가 일어나지 않는 경우는 둘 다 스왑이 없다. 페이지 폴트가 일어날 때 LFD는 페이지 p를, KKG는 페이지 p'를 제거한다고 가정하자.

KKG가 p'를 제거한 직후 p'가 다시 요청되면 KKG는 무조건 추가 스왑이 발생한다. 반면 LFD는 p를 제거했으므로 p'가 메모리에 있을 가능성이 있어 스왑이 발생하지 않을 수 있다. 따라서 LFD는 다른 알고리즘과 같거나 더 적은 스왑을 보장하므로 최적이다.

### Convoy Effect vs Starvation
- **Convoy effect**: 시간이 오래 걸리는 프로세스로 인해 다른 프로세스의 실행이 느려지고 평균 대기시간이 길어지는 현상. FCFS에서 발생 가능.
  - 예: P1(100ms), P2(5ms), P3(5ms)일 때
    - P1→P2→P3: 평균 대기 = (0+100+105)/3 = 68ms
    - P2→P3→P1: 평균 대기 = (0+5+10)/3 = 5ms
- **Starvation(기아)**: 어떤 프로세스가 무기한으로 대기하며 CPU 소유권을 얻을 수 없는 현상. SJF에서 발생 가능. **aging**으로 해결.

### Busy Wait
프로세스/스레드가 작업 실행 전에 만족 조건을 지속적으로 확인하는 동기화 기술.

```
while True:
    if complete_state():
        break
```

- 운영체제에서 상호배제 달성에 사용
- 우선순위에 따라 작업 변경이 불가능해 비효율적
- 대기시간이 길 때 CPU 자원 낭비가 심함
- 대부분의 경우 안티패턴으로 분류됨

### 운영체제와 펌웨어의 차이
1. **메모리 구조**: 펌웨어는 ROM(비휘발성 메모리) 하나를 쓰는 반면, 운영체제는 휘발성/비휘발성 메모리를 계층화해서 사용
2. **프로그램 설치**: 펌웨어는 자유 설치 불가, 미리 설치된 프로그램 기반의 업데이트만 가능. 운영체제는 정기 업데이트되며 그 위에 프로그램을 자유롭게 설치 가능
3. **종류**: 펌웨어는 키보드, 세탁기 등에 들어가는 소프트웨어. 운영체제는 MacOS, WindowOS 등이 대표적
